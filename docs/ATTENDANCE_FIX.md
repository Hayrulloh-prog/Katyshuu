# Исправление проблемы с циклом приход-уход

## Описание проблемы

После сканирования сотрудника не записывалось время ухода. Система должна была работать в цикле: приход → уход → приход → уход, но время ухода не обновлялось.

**Основная проблема**: После регистрации только второй скан работал правильно (записывал уход), а все последующие сканы только приходили, но не уходили.

## Причины проблемы

### 1. Неправильное использование upsert

В логике checkin использовался `upsert` с уникальным ключом `employeeId_date`, что не позволяло создавать несколько записей за один день.

**Было (неправильно):**
```javascript
// Upsert не позволяет создавать несколько записей за день
const attendance = await prisma.attendance.upsert({
  where: {
    employeeId_date: {
      employeeId: parseInt(employeeId),
      date: localToday
    }
  },
  update: {
    checkInTime: new Date(),
    // ...
  },
  create: {
    // ...
  }
});
```

**Стало (правильно):**
```javascript
// Простое создание новой записи для каждого check-in
const attendance = await prisma.attendance.create({
  data: {
    employeeId: parseInt(employeeId),
    date: localToday,
    checkInTime: new Date(),
    location: location ? `${location.latitude}, ${location.longitude}` : null,
    deviceFingerprint
  }
});
```

### 2. Неправильная логика поиска записей

Поиск записей велся по `checkInTime`, что не учитывало все записи за последние 24 часа.

**Было (неправильно):**
```javascript
where: {
  employeeId: employee.id,
  checkInTime: {
    gte: twentyFourHoursAgo
  }
}
```

**Стало (правильно):**
```javascript
where: {
  employeeId: employee.id,
  createdAt: {
    gte: twentyFourHoursAgo
  }
}
```

## Как теперь работает система

### Цикл приход-уход:
1. **Первое сканирование** → check-in (создается новая запись #1)
2. **Второе сканирование** → checkout (обновляется запись #1)
3. **Третье сканирование** → check-in (создается новая запись #2)
4. **Четвертое сканирование** → checkout (обновляется запись #2)
5. **Пятое сканирование** → check-in (создается новая запись #3)
6. **Шестое сканирование** → checkout (обновляется запись #3)

### Ограничения:
- Максимум 5 полных циклов (приход-уход) за 24 часа
- Каждый check-in создает новую запись
- Каждый checkout обновляет последнюю незавершенную запись

## Безопасность и эффективность

✅ **Безопасно:**
- Сохраняются все ограничения (5 циклов за 24 часа)
- Проверка на незавершенные записи перед checkout
- Валидация данных устройства и геолокации

✅ **Эффективно:**
- Простая логика без сложных upsert операций
- Быстрый поиск по индексу `createdAt`
- Минимальное количество запросов к БД
