# Исправление логики выбора аккаунта

## Описание проблемы

После выбора Google аккаунта появлялся экран "Аккаунт тандаш" (Выбор аккаунта), даже если у сотрудника уже был аккаунт у другого менеджера. Это мешало работе сотрудников, которые хотят работать у нескольких менеджеров с одним аккаунтом.

## Решение

### Изменения в клиентской части

**Файл:** `client/src/pages/QRScanPage.jsx`

1. **Упрощена функция `handleOAuthCallback`**:
   - Удалена логика показа экрана выбора аккаунта
   - Теперь всегда переходит сразу к регистрации
   - Сотрудник может работать у нескольких менеджеров с одним аккаунтом

2. **Удален рендеринг экрана выбора аккаунта**:
   - Удален case `account-selection` из `renderContent()`
   - Удалены неиспользуемые функции `handleUseExistingAccount` и `handleJoinNewManager`

### Серверная часть

Серверная часть уже поддерживает работу с несколькими менеджерами:
- Эндпоинт `/api/oauth/register` позволяет создавать несколько записей сотрудника с разными managerId
- Проверка по email, googleId и номеру телефона работает корректно

## Результат

Теперь после выбора Google аккаунта пользователь сразу переходит к регистрации имени, фамилии и телефона, без экрана выбора аккаунта. Сотрудник может:
- Работать у нескольких менеджеров с одним Google аккаунтом
- Регистрироваться у нового менеджера, даже если уже работает у другого
- Использовать те же данные (имя, фамилия, телефон) для разных менеджеров
