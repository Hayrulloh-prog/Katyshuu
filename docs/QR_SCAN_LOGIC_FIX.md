# Исправление логики сканирования QR-кодов

## Описание проблемы

Исходная система имела проблемы с логикой сканирования QR-кодов:
1. Неправильное определение первого и второго сканирования
2. Сотрудники сохранялись не у того менеджера
3. Отсутствие выбора аккаунта при сканировании другого QR-кода
4. Сотрудники удалялись из панели старого менеджера при регистрации у нового

## Реализованные изменения

### 1. Обновленная логика определения типа сканирования (`server/routes/qr.js`)

- **Первый скан**: `isFirstScan: true, isManagerRegistration: true`
  - Перенаправление на страницу регистрации менеджера
- **Второй скан**: `isSecondScan: true, isEmployeeRegistration: true`
  - Регистрация сотрудника для конкретного менеджера
- **Отметка посещаемости**: `isAttendanceScan: true`
  - Обработка прихода/ухода сотрудника

### 2. Проверка существующих аккаунтов (`server/routes/oauth.js`)

Новый маршрут `/api/oauth/check-accounts`:
- Проверяет наличие аккаунтов сотрудника у других менеджеров
- Возвращает информацию о существующих аккаунтах
- Позволяет выбрать между существующим аккаунтом или созданием нового

### 3. Компонент выбора аккаунта (`client/src/components/AccountSelection.jsx`)

- Отображает существующие аккаунты сотрудника
- Предлагает выбор:
  - Использовать существующий аккаунт
  - Создать новый аккаунт у текущего менеджера

### 4. Обновленная логика регистрации (`server/routes/oauth.js`)

- Поддержка регистрации с указанием `managerId`
- Проверка существования сотрудника только у конкретного менеджера
- Возможность иметь несколько аккаунтов у разных менеджеров

### 5. Интеграция с QRScanPage (`client/src/pages/QRScanPage.jsx`)

- Обработка различных типов сканирования
- Автоматическая проверка существующих аккаунтов
- Сохранение данных менеджера для правильной регистрации

## Новый процесс сканирования

### Первый скан QR-кода
1. Пользователь сканирует QR-код
2. Система определяет `isFirstScan: true`
3. Перенаправление на страницу регистрации менеджера
4. Менеджер регистрируется и привязывается к QR-коду

### Второй скан QR-кода
1. Пользователь сканирует тот же QR-код
2. Система определяет `isSecondScan: true`
3. Пользователь выбирает провайдера аутентификации
4. Система проверяет наличие существующих аккаунтов
5. Если аккаунты существуют у других менеджеров - показывает выбор
6. Пользователь выбирает:
   - Использовать существующий аккаунт (отметка посещаемости)
   - Создать новый аккаунт (регистрация у текущего менеджера)

### Последующие сканирования
1. Пользователь сканирует QR-код
2. Система определяет `isAttendanceScan: true`
3. Автоматическая аутентификация или выбор провайдера
4. Обработка прихода/ухода

## Преимущества новой логики

✅ **Правильное определение типа сканирования**
- Первый скан всегда для регистрации менеджера
- Второй скан для регистрации сотрудника
- Последующие для отметки посещаемости

✅ **Сохранение у правильного менеджера**
- Сотрудник всегда привязывается к менеджеру QR-кода
- Поддержка нескольких аккаунтов у разных менеджеров

✅ **Выбор аккаунта при необходимости**
- Проверка существующих аккаунтов
- Предложение выбора между аккаунтами
- Сохранение данных в панелях всех менеджеров

✅ **Обратная совместимость**
- Поддержка старых QR-кодов
- Плавный переход на новую логику

## Вывод

Новая логика полностью решает поставленные задачи:
1. Первый скан регистрирует менеджера
2. Второй скан регистрирует сотрудника
3. Сотрудник сохраняется в панели правильного менеджера
4. При сканировании другого QR-кода предлагается выбор аккаунта
5. Сотрудник не удаляется из панели старого менеджера при регистрации у нового
